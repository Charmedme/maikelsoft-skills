## Scan the tools

Look at the tools of this session before you research. Do not ask the human for a fact that a tool can give.

| Group | Look for | Use it for |
|-------|----------|------------|
| Ticket system | Jira, Azure DevOps, GitHub, GitLab, Linear | Existing items on the subject, templates, the push |
| Documents | Confluence, SharePoint or Microsoft 365, Google Drive, the claude.ai Project, the repository | Requirements, process descriptions, earlier decisions |
| Design | Design tokens in the repository, Storybook, Figma, Penpot, Canva, Design artifacts | The prototype |
| Web | Web search | Domain rules, laws, standards, how other products solve it |

Show the result in one table of at most 6 rows: group, tool found or not, what you use it for. When a group has no tool, say in one line which connector can help. Do not stop the run for it.

## Research

Answer these questions, each with its source:

1. **Existing work.** Which items in the ticket system are about this subject? Note their links: phase 6 uses them for the duplicate check.
2. **The current situation.** What do the documents and the product say about how it works now? Who uses it?
3. **The domain.** Which rules, laws, or standards apply? Use primary sources: the law, the standard, the official docs.
4. **Other products.** How do 2 or 3 other products solve the same need? Use this for ideas, not as a requirement.
5. **Constraints.** Which systems, data, or technologies does the request name or need?

Use sub-agents when you have them, one for each question, so that they work at the same time.

## Done

Write the "Sources" section: one row for each source, with what it gave and the link. Mark each fact that you cannot confirm as `UNCONFIRMED:`. Do not make decisions here: list the open points for phase 2.
