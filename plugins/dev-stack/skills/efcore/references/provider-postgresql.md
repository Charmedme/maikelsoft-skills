## Packages and versions

| Package | Version | Note |
|---------|---------|------|
| `Npgsql.EntityFrameworkCore.PostgreSQL` | 10.0.x | The EF provider (EFCore.PG). Depends on Npgsql 10. |
| `EFCore.NamingConventions` | 10.0.x | snake_case names (DATA-09). Not an official package. It can come out later than a new EF major version. |
| `Npgsql.EntityFrameworkCore.PostgreSQL.NodaTime` | 10.0.x | Only when DATA-10 picks NodaTime. |

PostgreSQL 18 is the current version. Ask the human before you add a package (stack rule 5).

## Registration

```csharp
services.AddDbContext<AppDbContext>((sp, options) => options
    .UseNpgsql(connectionString, npgsql =>
    {
        npgsql.SetPostgresVersion(18, 0);
        npgsql.EnableRetryOnFailure();
    })
    .UseSnakeCaseNamingConvention()
    .AddInterceptors(sp.GetRequiredService<AuditInterceptor>()));
```

- `SetPostgresVersion(18, 0)`: EF writes SQL for that version. It turns on PostgreSQL 18 features such as `uuidv7()` translation and virtual generated columns. EFCore.PG 11 assumes 16 when you do not set it.
- `EnableRetryOnFailure()`: Npgsql marks serialization failures (40001) and deadlocks (40P01) as transient. With retries on, run each explicit transaction inside the execution strategy (see `writes.md`).

## Naming (snake_case)

PostgreSQL folds names without quotes to lowercase. EF quotes PascalCase names, so each hand-written query needs quotes too (`SELECT "CreatedAt" FROM "Orders"`). `UseSnakeCaseNamingConvention()` maps `CreatedAt` to `created_at` and `Orders` to `orders`, also for keys, indexes, and constraints (`pk_orders`, `ix_orders_tenant_id`).

When the project also uses Dapper, set `DefaultTypeMap.MatchNamesWithUnderscores = true`.

In an existing project with PascalCase names, the convention renames all tables and columns in the next migration. Ask the human first.

## Keys and UUIDv7

- A `Guid` key gets a UUIDv7 value on `Add`. The EF provider EFCore.PG 9+ generates it (`NpgsqlSequentialGuidValueGenerator`), not the Npgsql driver. Dapper inserts do not get it. Do not set `Id = Guid.NewGuid()`.
- PostgreSQL 18 has the `uuidv7()` SQL function. Use it in a column default (`HasDefaultValueSql("uuidv7()")`) only when other writers insert rows without EF.
- `int` and `long` keys use `GENERATED BY DEFAULT AS IDENTITY`, not `serial`.

## Concurrency token (xmin)

```csharp
[Timestamp]
public uint Version { get; set; } // maps to the xmin system column
```

Or `b.Property(o => o.Version).IsRowVersion();` on a `uint` property. PostgreSQL changes `xmin` on each update. EF adds no column to the table.

`UseXminAsConcurrencyToken()` is the old API. It is obsolete since EFCore.PG 7 and EFCore.PG 10 does not have it.

## Enums

DATA-12 default is a string column. When the human picks a PostgreSQL enum type, map it in `UseNpgsql` (EFCore.PG 9+):

```csharp
.UseNpgsql(connectionString, o => o
    .SetPostgresVersion(18, 0)
    .MapEnum<Mood>("mood"))
```

- EF creates the type in a migration (`CREATE TYPE mood AS ENUM (...)`).
- A new enum value needs `ALTER TYPE ... ADD VALUE` in a migration. To remove a value, you must create the type again.
- The old method (`NpgsqlConnection.GlobalTypeMapper.MapEnum<T>()` plus `HasPostgresEnum`) is obsolete.

## Time

| .NET | PostgreSQL | Rule |
|------|------------|------|
| `DateTimeOffset` | `timestamptz` | The offset must be zero. Npgsql throws for another offset. |
| `DateTime` with `Kind = Utc` | `timestamptz` | Npgsql throws for `Local` or `Unspecified`. |
| `DateTime` with another kind | `timestamp` | No time zone. Do not use it for instants. |
| `DateOnly` | `date` | Npgsql 10 reads `date` as `DateOnly`. |
| `TimeOnly` | `time` | Npgsql 10 reads `time` as `TimeOnly`. |
| `TimeSpan` | `interval` | |

`timestamptz` stores a UTC instant, not a time zone. Store an IANA zone ID in its own column when the zone of the user matters. Do not set `Npgsql.EnableLegacyTimestampBehavior` to hide a local time.

## Case-insensitive text

PostgreSQL compares text with case. The same LINQ query returns other rows than on SQL Server. Options, best first:

1. A nondeterministic ICU collation on the column:

   ```csharp
   modelBuilder.HasCollation("case_insensitive", locale: "und-u-ks-level2", provider: "icu", deterministic: false);
   b.Property(i => i.Email).UseCollation("case_insensitive");
   ```

   PostgreSQL 18 also supports `LIKE` on a column with a nondeterministic collation.

2. `EF.Functions.ILike(i.Number, term + "%")` for a search query.
3. A normalized column with an index (for example a lowercase copy).

`citext` is the older option. Do not use `ToLower()` in the query.

## JSON and arrays

- A complex type with `ToJson()` maps to `jsonb`. This replaces the old POCO mapping with `[Column(TypeName = "jsonb")]`.
- `string[]` and `List<T>` of primitives map to PostgreSQL arrays.
- EFCore.PG 10 translates `array.Contains(x)` to `x = ANY(array)`. When the array column has a GIN index, EF uses `@>`, which the index can serve.

## Indexes from the model

```csharp
b.HasIndex(p => p.Tags).HasMethod("gin");
b.HasIndex(p => p.Name).HasFilter("is_active").IsCreatedConcurrently();
```

- `HasFilter` makes a partial index. Write the filter in SQL with the database names (snake_case).
- `IsCreatedConcurrently()` makes `CREATE INDEX CONCURRENTLY`, which does not block writes. It cannot run in a transaction: `Migrate` and a bundle run that step without one. An idempotent script puts each step in a `DO` block, and PostgreSQL rejects the statement there (SQLSTATE 25001). Run that index from a separate, non-idempotent script, or from a pre-deploy SQL file (SKILL.md rule 32a). A plain `CREATE INDEX` on a large live table blocks writes for the whole build.
- `IncludeProperties` adds covering columns.
- Index design (column order, skip scan in PostgreSQL 18, GIN or B-tree) is in `dev-stack:postgresql`.

## Generated columns

PostgreSQL 18 makes generated columns virtual by default. In EFCore.PG, `HasComputedColumnSql(sql)` without `stored: true` makes a virtual column on 18. Add `stored: true` when you need an index on the column or the old behavior.

```csharp
b.Property(p => p.PriceWithVat).HasComputedColumnSql("price * 1.21", stored: true);
```

## Error codes

| SQLSTATE | `PostgresErrorCodes` | Meaning |
|----------|----------------------|---------|
| 23505 | `UniqueViolation` | Unique index or key violation |
| 23503 | `ForeignKeyViolation` | Foreign key violation |
| 40001 | `SerializationFailure` | Retry the whole transaction (the retry strategy does it) |
| 40P01 | `DeadlockDetected` | Retry the whole transaction |

## Shared data source with Dapper

When EF and Dapper share one `NpgsqlDataSource`, pass the data source to `UseNpgsql(dataSource, ...)`. Map enums and plugins on the data source builder and in the EF options both. Dapper rules are in the `dapper-postgres` skill.
