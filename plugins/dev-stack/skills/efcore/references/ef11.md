# EF Core 11

Read this file only when the project uses EF Core 11. Status on 2026-10-16: release candidate 2 (`11.0.0-rc.2.26504.105`). Microsoft plans GA for November 2026. EF Core 11 needs .NET 11, which is not an LTS release. EFCore.PG 11 is at RC 1. Look up the status again before you use these facts (stack rule 2).

The rules of `SKILL.md` stay valid. This file lists what changes.

## Breaking changes that affect most projects

| Change | Effect | What to do |
|--------|--------|------------|
| Microsoft.Data.SqlClient 7 | The Azure and Entra ID authentication code moved out of SqlClient. `ActiveDirectoryPassword` is obsolete. | For Entra ID, add the package `Microsoft.Data.SqlClient.Extensions.Azure` (ask the human, stack rule 5). Use `ActiveDirectoryDefault` or managed identity. |
| SQL Server compatibility level default 160 | EF writes SQL Server 2022 SQL (`LEAST`, `GREATEST`). SQL Server 2019 and older fail on some queries. | Set `UseCompatibilityLevel` to the real level. |
| `Migrate` throws when the assembly has no migrations | A project that calls `Migrate` without migrations fails at startup. | Remove the call, or configure `RelationalEventId.MigrationsNotFound`. |
| Split queries throw `DbQueryConcurrencyException` | EF 10 and older returned empty collections when data changed between the split statements. EF 11 throws. | Retry the query, run it in a snapshot or serializable transaction, or use a single query. |
| Owned JSON collections without a key are obsolete | Warning `OwnedEntityMappedToJsonCollectionWarning`. | Move to `ComplexCollection(..., b => b.ToJson())`. |
| `Property()` no longer configures a primitive collection | A `List<int>` configured with `Property` becomes a scalar. | Use `PrimitiveCollection()`. |
| `EFOptimizeContext` MSBuild property removed | The build ignores it. | Use `EFScaffoldModelStage` and `EFPrecompileQueriesStage`. |
| Tools packages no longer reference `Microsoft.EntityFrameworkCore.Design` | `dotnet ef` cannot find the design package. | Add a direct reference to `Microsoft.EntityFrameworkCore.Design` with `PrivateAssets="all"`. |
| `SqlVector<T>` properties not loaded by default | Vector properties are `null` on loaded entities. | Project them explicitly when needed. |
| EFCore.PG 11 assumes PostgreSQL 16 | EF writes SQL for 16 when the code sets no version. | Set `SetPostgresVersion(18, 0)`. |

## New APIs that change code

- `FullJoin` (.NET 11) translates to `FULL JOIN`.
- `MaxByAsync` and `MinByAsync` translate to SQL.
- `EF.Functions.JsonPathExists()` (SQL Server `JSON_PATH_EXISTS`).
- `Contains` on a JSON collection uses `JSON_CONTAINS` at compatibility level 170.
- Complex types and JSON columns work with TPT and TPC inheritance.
- You can configure complex type properties with a chained lambda: `Property(e => e.Details.Description)`.
- Full-text catalogs and indexes in the model (`HasFullTextCatalog`, `HasFullTextIndex`), and `FreeTextTable` and `ContainsTable` queries.
- Vector indexes (`HasVectorIndex`) and `VectorSearch()` on SQL Server 2025. Both are experimental in SQL Server.
- Temporal table period columns can map to CLR properties.
- `dotnet ef database update <name> --add` adds and applies a migration in one step. Use it only on a local database.
- EFCore.PG 11: PostgreSQL 18 temporal constraints (`HasWithoutOverlaps()`, `HasPeriod()`).
- The model snapshot records the latest migration ID, so Git shows a conflict when two branches add a migration.

## Analyzer

EF1004 reports `ToAsyncEnumerable()` on an EF query. Use `AsAsyncEnumerable()`.

## Upgrade steps

Upgrade only when the task asks for it (stack rule 1).

1. Change the target framework to `net11.0` and all `Microsoft.EntityFrameworkCore*` packages and the `dotnet-ef` tool to the same 11.0 version.
2. Add the `Design` package reference, and `Microsoft.Data.SqlClient.Extensions.Azure` when the app uses Entra ID.
3. Set the compatibility level or the PostgreSQL version explicitly.
4. Build with `-warnaserror`. Fix the obsolete warnings (owned JSON collections, `ActiveDirectoryPassword`).
5. Run `dotnet ef migrations has-pending-model-changes`. Add a migration for the snapshot change when it reports one, and read it.
6. Run all integration tests against the real engine.

Done when the build, the pending-changes check, and the tests pass.
