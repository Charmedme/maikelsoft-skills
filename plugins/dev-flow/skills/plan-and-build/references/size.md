# Size

The size sets how much of each phase you do. All phases and all gates stay. Only the depth changes.

| | Small | Medium | Large |
|---|---|---|---|
| Signal | One behaviour, one or two files | One feature, more than one layer | More than one feature, or more than 10 tickets |
| Research | The code that the change touches | The code, the docs, the primary sources | The same, with one sub-agent for each area |
| Grill | One round, max 6 questions. Always include the errors and the edge cases | Rounds until no question is open | The same, one branch of the design tree at a time |
| Specs | One spec | One spec | One spec for each feature |
| Tickets | 1 to 3 | 3 to 10 | One set for each spec. The plan gives the order of the sets |
| Prototype | The smallest thing that shows the behaviour | One logic or UI prototype | One prototype for each risky spec |

When the work is larger than "large", tell the human. Suggest to split it into more than one run, one run for each part that can work alone.
