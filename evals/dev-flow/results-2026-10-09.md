# plan-and-build test results, rounds 1 and 2

These rounds test the skill `plan-and-build` of the plugin `dev-flow`. The skill joins six skills of Matt Pocock into one flow: grill-me, to-spec, to-tickets, to-questionnaire, prototype, and implement.

## Method

- Each run had its own agent: 3 runs for each variant and each eval, 36 runs in total.
- The agent never saw the answer sheet in `humans/`. The orchestrator played the human and replied only from the sheet. The agent stopped at each question, and the orchestrator sent the reply.
- `score.py` scored the `check` assertions. One grader agent for each run scored the `judge` assertions, with one line of evidence for each.
- The variants:
  - **baseline**: the six source skills. The human called them one by one, in the order grill-me, to-spec, to-tickets, prototype, implement.
  - **v1**: the first draft of `plan-and-build`.
  - **v2**: v1 with the fixes from round 1.

The evals:

- **todo-due-dates** (A): add due dates and an overdue view to a small Python tool. At the prototype, the human asks for one change.
- **chores-rotation** (B): rotate household chores each week, on a small web page with an `AGENTS.md`. At the prototype, the human says "No": the rotation must skip a person who is away. Only Bram knows how the house keeps that list, so a questionnaire is necessary.
- **todo-alias** (C): a small change of one line. `ls` becomes a short name for `list`.

## Results

### Checks (score.py)

| Eval | baseline | v1 | v2 |
|------|----------|----|----|
| A | 18/21 | 24/24 | 24/24 |
| B | 26/30 | 33/33 | 32/33 |
| C | 12/15 | not run | 18/18 |

Almost all baseline failures are language errors in the documents: 12 to 57 errors in each run. The skill runs had 0 errors, except one run of v2 with 1 error.

## Findings

- **The skill asks fewer questions and writes less.** In eval A, v2 needed half of the turns of the baseline. The work documents had about 30 % fewer words, and each document passed the language checker.
- **The human calls nothing.** With the baseline, the human must know the order of six skills and call each one. With the skill, the human only answers.
- **The prototype gate holds.** Each skill run stopped at the prototype and asked "Is this what you want?" before it changed the code. Two baseline runs in eval C went from the prototype to the code without a question. One baseline run in eval B did not show the changed prototype again.
- **v1 skipped the errors on small work.** One v1 run did not ask about errors and used exit code 2 instead of 1. v2 always asks about errors and edge cases. This includes small work. Two v2 runs proposed exit code 2, and the human corrected it.
- **v2 keeps the questionnaire subject with the third person.** After "Bram knows", v2 put each absence question in the questionnaire. When Bram's answers left a gap, v2 asked one question: send a follow-up, or use the recommended answers as assumptions. Two graders scored this question as a failure. The assertion does not separate this process question from a subject question. The next round needs a clearer assertion.
- **The small change asks 6 questions.** The v2 limit for small work is 6 questions, with errors and edge cases always included. The assertion of eval C allows 5. The assertion is older than v2.
- **The project guide wins.** In eval B, each skill run used the branch and commit rules of `AGENTS.md`. In v1, two runs of eval A used `due-dates` instead of `feat/due-dates`. In v2, each run used `feat/<slug>`.

## Changes after round 2 (v2.1, not tested in a round)

- Each gate question, also G4, has a recommended answer. One v2 run asked G4 without one.
- The skill does not ask for the name of the sender of a questionnaire.
- The two status lines in the plan template use `|`. They gave a checker warning in each run.

## Limits

- **Sub-agents.** The test agents could not start sub-agents. The research, the build, and the review ran in one agent. The skill uses sub-agents when it has them. This part is not tested.
- **One orchestrator.** The orchestrator knew the expected results. It replied only from the answer sheets. When a question was not on the sheet, it replied "Use your recommendation".
- **Same model.** All runs used the same model. Run the eval set again when the model changes.
- **No real browser.** The agents checked the web pages with Node.js, not in a browser.

## Changes to the eval set after round 2

The scores above use the assertions of round 2. Two assertions changed after round 2, for the next round:

- **todo-alias:** "at most 5 questions" is now "at most 6 questions". The approved design of v2 allows 6 questions for small work, with the errors and the edge cases always included.
- **chores-rotation:** the questionnaire assertion now allows one question about the process: send a follow-up, or use assumptions. The skill asks this question on purpose. The assertion still fails when the agent asks the human for the answer to an absence question.
