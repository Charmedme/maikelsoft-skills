# Results 2026-10-12: grill phase

Eval: `grill-vague` in `evals.json`. The request is vague: "Make me a skill for my Monday status mail to the team." A simulated human answers from `humans/monday-mail.md`. The sheet holds 7 hidden facts (H1 to H7). The human gives a fact only when a question touches its topic.

Method: one separate agent (Sonnet) for each run, and 3 runs for each version. A new agent played the human for each reply. One grader agent scored each run. A script ran `skillcheck.py`.

## Versions

- v1: `build-skill` 1.0.0. One round of questions, then a concept.
- v2: grill first, in rounds, with a brief and gate G1.
- v2.1: v2 plus three fixes from the v2 results. Round 1 always asks the gate, the walkthrough, and the bad case. The walkthrough question has a fixed text. G1 is its own message.

## Limits of these tests

- The simulated human was generous. One broad question sometimes gave several hidden facts. So v1 also found most facts. The gain shows most in how the agent asks.
- The graders could see the version in the path.
- The operator stopped v2.1 run 2 during the build. A second agent finished it from the log and the brief. Its first skill files have a time before the logged approval. The orchestrator most likely sent the approval message before the stop. This run is weak evidence for "no skill file before approval".
- Nobody ran a built skill on real data. No trigger test ran in this round.
- `build-agent` uses the same grill reference. No separate test ran for it in this round.
