# Test results: ux-design 0.1.0

This file records the tests of the ux-design plugin before version 0.1.0. The plugin version in the tests was v1 to v4. Version 0.1.0 is v4.

## Setup

- Product: Fieldline, a fictional field-service product. Stories: assign unplanned work (a list), a callback request (a form), and the parts status (a detail panel).
- Fixtures: `fieldline` (a strong design system), `fieldline-empty` (no design system), and `fieldline-faulty` (a design system with 9 planted faults, refer to `faults.json`).
- Variants: `baseline` (the same prompt, no plugin) and the plugin versions. Each variant ran 3 times for each case.
- Runner: `run.py` starts `claude -p` in a copy of the fixture. The prompt is `runner.md`.
- Measures: `score.py` counts checker issues, tells, files, and faults. `extract.py` asks fixed questions and gives the agreement of the run pairs. `grade.py` runs blind pairwise graders, with the order of A and B swapped.
- A design document shows its variant by its format (source tags, rule IDs). Thus the design grades are not fully blind. The mockup grades are blind.

## Iteration 1 (Opus, v1, strong fixture)

The plugin won on states, on the design system, and on grounded decisions. The baseline won on product extras. The rule "default is the normal case with real data" made the form start filled in. Screen names were different in each run.

## Iteration 2 (Opus, v2, all fixtures)

| Fixture | Measure | Baseline | v2 |
|---------|---------|----------|----|
| Empty | Shared style files | 0 of 6 runs | 6 of 6 runs |
| Empty | Determinism (assign, form) | 0.78, 0.72 | 0.94, 1.00 |
| Empty | Tells for each run | 6 to 32 | 0 |
| Faulty | Faults named (of 9) | 8, 9, 9 | 8, 8, 9 |
| Faulty | Faults copied into the mockups (of 9) | 6, 6, 7 | 0, 0, 0 |

The design documents of v2 won on each criterion. The mockups lost on clarity (10-26) and on product detail (5-30). The baseline showed the business rules at the point of decision. It also numbered the steps of a fixed-order task and showed a summary before the primary action.

## Iteration 3 (Sonnet, baseline, v2, v3)

The v3 changes: business rules at the point of decision, a summary before a commit action, and numbered sections for a fixed-order task. Also a small "Proposed" badge, and realistic data with edge data. Against v2, v3 won clarity (19-11) and product detail (21-7). v3 lost some completeness: v2 won states (18-9) and the design system (15-9).

## Iteration 4 (Sonnet, baseline, v3, v4)

The v4 changes: each error kind is its own state, a failure paths table that `uxcheck.py` checks, and each opportunity in its own `proposed-op-<n>` frame.

| Criterion | Baseline vs v4 | v3 vs v4 |
|-----------|----------------|----------|
| Design: thought through | v4 30-0 | v4 22-8 |
| Design: grounded | v4 27-2 | v4 16-13 |
| Design: buildable | v4 30-0 | v4 20-9 |
| Mockups: states | v4 30-0 | v4 26-2 |
| Mockups: design system | v4 20-6 | v4 18-3 |
| Mockups: specific | v4 22-7 | v3 17-13 |
| Mockups: clarity | v4 20-10 | v3 18-12 |

Determinism (assign, form, parts, empty, faulty): baseline 0.81, 0.90, 0.89, 0.83, 0.75. v4 1.00, 0.90, 0.89, 0.89, 0.92. On the faulty fixture, v4 named 8 or 9 faults and copied 0. Cost for each run: baseline $0.60, v4 $1.47.

## Harness faults found

- The checker did not read tokens from `file://` style sheets. It now reads the CSS from disk.
- The CLI can print extra lines after the result. The parsers now read the last result line. One false determinism value (0.28, real 0.89) came from this fault.
- Full-page screenshots were too tall for the graders. The checker now makes one screenshot for each frame.
