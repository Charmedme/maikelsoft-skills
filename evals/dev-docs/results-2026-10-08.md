# dev-docs test results, 2026-10-08

This file records the tests that came before release 1.0.0. The eval set is in [evals.json](evals.json).

## Method

Each run had its own agent. No agent saw the skill author's outputs, the original gron README, or the other runs. There were four variants:

- **A**: no skill.
- **B**: only the leading word ("Write in ASD-STE100 Simplified Technical English", or "Begrijpelijk Nederlands B1").
- **v1**: the first version of the skills.
- **v2**: the version after the fixes from v1.

The skill agents got the folder with all 10 skills. They selected the skill from the descriptions. The numbers come from the checker of dev-docs 1.0.0. The two rewrite cases use `--source`.

## Findings

- **Length.** Without a skill, the README had 1,600 to 2,100 words, and the agent put a list of bugs in it. With the skill, it had 590 to 840 words.
- **Facts.** No variant invented an option. In case 2, A, B, and v1 added a missing `;` to the documented output. They told the reader in their report, but the page now shows output that gron did not print. Only v2 kept the code and reported the source error. The v2 rule "do not fix a source error silently" causes this difference.
- **Anchors.** In case 3, v1 changed 3 heading anchors, so links from other pages can break. v2 kept each anchor. It used an explicit ID (`{#prerequisites}`), which works on this Jekyll site. GitHub does not support explicit IDs.
- **Leading word.** The leading word alone (B) gave good sentences, but it did not stop long sentences in a long document. The checker loop in the skill stops them.
- **No-op lines.** No variant used an em-dash, and no variant replaced "run" with "operate". The technical-verb rule now applies only in strict mode, where a word check can remove those verbs. The em-dash rule stays, because the checker enforces it and other models can behave differently.
- **Selection.** In all 14 skill runs, the agent selected a skill that fits. In case 3, v1 selected `doc-tutorial` and v2 selected `doc-howto`. Both fit a page that mixes a lesson and a task.

## Smoke test of the other skills

One run for each skill gave these fixes before the release:

- A fallback for unattended runs (5 of 8 runs had no rule when nobody could answer).
- Checker: a Keep a Changelog version heading is not a dash. The checker reads table cells. A long quote counts as its words. A new `--comments` mode reads comments in source code.
- Skill text:
  - program-wide sections in a CLI reference
  - no invented ratings in an ADR
  - the link for a first release
  - the Go convention for doc comments

## STE knowledge of the model

Before the tests, the author model classified 60 words as approved or not approved without the dictionary. Then a script compared the answers with the dictionary. The score was 55 of 60 (92%). Strict mode is thus a best effort. It reports each word that it is not sure about, and it does not claim compliance.

## Limits of these tests

- The test has one run for each variant and case. A second run can give different numbers.
- The subagents could not write a report file, so they gave their reports as text.
- The same model family wrote the skills and ran them.
